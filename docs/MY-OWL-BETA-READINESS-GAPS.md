# MY OWL — Beta Readiness Gaps

Status as of 2026-10-30: **not ready for Private Beta, Public Beta, or V1 launch**.

- The real rescan worker resolves the repository's current commit, runs the enabled productization path, persists an `AFFECTED` finding tied to the approved change, and marks the durable rescan job complete.
- The rollout flag is an explicit rollback boundary: with `PROVIDER_INTELLIGENCE_V1_ENABLED=false`, approved dynamic rules are not loaded by the worker and no dynamic finding is produced.
- The provider-rule review API now filters candidates to the current workspace plus intentionally unassigned global candidates; workspace-owned candidates are not cross-listed.
- The review preview now tests operation, model, endpoint, resource, parameter, response-field, domain, and auth/header evidence as bounded literal matches; it never executes submitted sample code.
- The protected provider-intelligence status route reports the 19-source catalog, parser/source health, approval/rescan queues, and worker metrics without exposing source bodies.
- The normalized scanner now carries explicit API-version literals from the TypeScript/JavaScript, Python, Go, Java/Kotlin, and C# adapters into the shared compatibility engine; package versions and generic `version` fields remain deliberately separate from API-version evidence.
- The API-version path is covered end to end locally: a detected Shopify retirement becomes a review candidate, approval queues a durable rescan, the worker resolves the current commit, and a matching static `apiVersion` literal produces an affected finding. This remains mocked GitHub evidence, not live production proof.

## Private Beta gate

Required before invitation-only use:

- frozen clean release commit and reproducible build;
- full typecheck, lint, build, and test suite pass on that commit;
- all registered rules covered by deterministic positive, negative, dynamic, wrong-provider, duplicate, and location fixtures;
- one real GitHub repository scan with an authenticated test tenant;
- tenant/repository authorization and webhook replay tests against the release build;
- worker stop/start, stale lease, duplicate delivery, retry, and restore rehearsal;
- explicit product copy that separates discovery from compatibility support;
- safe human-review gate for every suggested remediation or Draft PR.

## Public Beta gate

Private Beta evidence must be repeated across multiple tenants and repositories, with production observability, rate-limit capacity tests, migration/backup rehearsal, billing enforcement, legal consent, support/incident procedures, and measured scan-size/runtime limits.

## V1 gate

V1 additionally requires broad provider rule coverage with an evidence freshness policy, automated official-source ingestion with provenance and human promotion, stable cross-language semantics, documented false-positive/false-negative boundaries, reliable remediation verification, security review, data-retention controls, disaster recovery, and an operational SLO/error budget.

## Explicit non-claims

The current evidence does not establish that MY OWL automatically learns every provider API change, scans every GitHub repository end to end, safely generates a migration for every finding, or is secure/compliant/certified. Codex-run research and local fixtures are development evidence, not SaaS automation or production proof.
